# 服务器自动邮件提醒

`send-reminders` 是独立运行的命令，不依赖浏览器会话或外部机器人。默认仅模拟；只有显式添加 `--send` 才会发送。

## 行为

- 复用网站的填报窗口和未填报判断，仅处理启用、非测试账号。
- 通常在设定的开始日12:00开放；如该日休息，提前到最近实际工作日的同一时刻。管理员仍可修改通常开始日和时刻，窗口固定持续24小时。
- 整个统计周（上周六至本周五）都没有工作日时免填、不催填，也不列为漏报；调休上班日计入工作日。既有工时记录不删除、不改周次，下一次带出项目时跳过免填周。
- 提醒时刻为实际窗口开启后4小时。任务每分钟检查，但只有到点的那一分钟允许开始发送；不会提前发送或在错过后补发。
- 0工时已提交、仅请假已提交均不催填；邮件发到员工账号中维护的邮箱，管理员应及时停用离职账号并核对邮箱。
- 业务数据库通过 SQLite `mode=ro` 和 `query_only` 只读打开，不执行迁移、初始化或写入。
- 发信尝试保存在另一个 SQLite 数据库，以 `填报周 + 用户编号` 唯一约束防止重复发送。
- 每人单独发信，不使用抄送或群发收件人名单；正文只包含本人填报提示和网站入口。
- 每次发信前重查窗口、账号启用状态和提交状态。查询后立即提交仍可能与邮件发送交错，正文提示已提交者忽略。
- 无效邮箱不发送并报告错误。SMTP结果不确定、进程中断或结果记录失败时停止；该周已有尝试不会自动重试，避免重复邮件。
- `smtp_accepted` 表示邮件服务器已接受，不代表收件箱必达。提醒记录及日志不存密码、邮件正文或员工邮箱。

## 配置

业务配置沿用 `APP_DB`、`APP_BASE_URL`（实际发送必须是 HTTPS）、`APP_TIMEZONE`。

| 环境变量 | 用途 |
| --- | --- |
| `APP_SMTP_USERNAME` | 发件邮箱，同时作为 SMTP 登录账号 |
| `APP_SMTP_HOST` | 默认为 `smtp.gmail.com` |
| `APP_SMTP_PORT` | 默认为 `465`；仅支持隐式 TLS，不支持明文连接 |
| `APP_SMTP_PASSWORD_FILE` | 私有应用密码文件；不得写入代码或日志 |
| `APP_REMINDER_STATE_DB` | 独立发信记录路径；实际发送时必填，不得指向业务库 |

如由 systemd 注入名为 `gmail-app-password` 的凭据，可不设置 `APP_SMTP_PASSWORD_FILE`，命令从 `CREDENTIALS_DIRECTORY` 读取。凭据源文件应仅管理员可读，不放入网站目录、业务数据备份或 GitHub。

```text
workload-hub send-reminders                 # 模拟，不连接SMTP或写入发信记录
workload-hub send-reminders --check-auth    # 只验证SMTP授权，不发邮件
workload-hub send-reminders --send          # 实际发送，仍受窗口和去重限制
```

命令输出 JSON 摘要：统计周、未填报数、SMTP已接受数、跳过数、无效邮箱数及投递不确定数。异常返回非零退出码，供服务日志检查。

## 调度与维护

运行环境自行配置每分钟执行一次 `send-reminders --send`；程序按 `Asia/Shanghai` 和网站日历判断是否到达实际开启后4小时，不再将周五16:00写死。未到点、已过点、免填周和关闭窗口只输出状态，不连接SMTP、不发邮件。关闭调度器错过任务自动补跑及失败自动重试。

如周五休假、周四为工作日：周四12:00开放，周四16:00提醒，周五12:00关闭。连续休假向前找最近实际工作日。非免填周若产生窗口重叠，普通填报及邮件提醒均暂停，管理员检查系统设置和工作日历后再继续；不自动合并周次。

内置2026、2027年官方节假日及调休日期；管理员已有日历记录优先，不会被覆盖。[2027年国务院办公厅通知（政府网站转载）](https://www.forestry.gov.cn/lyj/1/szxx/20261105/695102.html)。后续年度需根据正式公告补充日历，不能把未维护的日历当成自动联网更新。

先确认本人测试邮件收到，再启用正式计划。维护时先停用调度器，再更新程序或凭据。若记录为 `pending` 或 `uncertain`，先核对发件箱/服务端投递结果，不能直接删除记录并重发。

专用读取接口仍独立存在，未增加员工邮箱返回字段。本功能由服务器本地读取员工邮箱；无需将邮箱和发信凭据交给 Dot。请停用外部机器人原有提醒任务，避免两套系统重复提醒。
