# 阿里云盘异地备份接入

系统每周六18:00先生成VPS本地数据库压缩包，并只保留最近3份。启用阿里云盘后，同一压缩包会再上传到指定云端目录；云端失败不会删除刚生成的本地备份，但定时任务会标记失败，便于排查。

## 选用的接入方式

阿里云盘不是rclone当前的原生后端。本项目改用开源的 `tickstep/aliyunpan` Linux命令行工具做一次性上传，不常驻后台，适合低内存VPS。该工具通过阿里云盘Open授权登录，支持Linux和 `upload 本地文件 目标目录` 命令。

- 项目与安装说明：https://github.com/tickstep/aliyunpan
- 命令手册：https://github.com/tickstep/aliyunpan/blob/main/docs/manual.md
- 阿里PDS OAuth说明：https://help.aliyun.com/zh/pds/drive-and-photo-service-dev/user-guide/application-access-details/

注意：`aliyunpan` 是第三方开源客户端，不是阿里云官方CLI。部署时应固定并记录版本，先人工验证上传，再启用定时任务。

## 部署时步骤

1. 从 `tickstep/aliyunpan` 的GitHub Releases下载与VPS架构相符的Linux amd64版本，固定版本安装到 `/usr/local/bin/aliyunpan`。
2. 创建配置目录并限制权限：

```bash
sudo install -d -o workload-hub -g workload-hub -m 700 /var/lib/workload-hub/aliyunpan
```

3. 以网站服务用户启动登录：

```bash
sudo -u workload-hub env ALIYUNPAN_CONFIG_DIR=/var/lib/workload-hub/aliyunpan /usr/local/bin/aliyunpan login
```

4. 将终端显示的链接复制到浏览器，由阿里云盘账号本人完成Open授权和扫码；不要把登录密码发给部署人员。
5. 在 `/etc/workload-hub.env` 设置：

```ini
APP_ALIDRIVE_ENABLED=true
APP_ALIDRIVE_CLI_BIN=/usr/local/bin/aliyunpan
APP_ALIDRIVE_CONFIG_DIR=/var/lib/workload-hub/aliyunpan
APP_ALIDRIVE_PATH=/载衡人力负荷备份
```

6. 手动执行并验证一次：

```bash
sudo systemctl start workload-hub-backup.service
sudo systemctl status workload-hub-backup.service
sudo journalctl -u workload-hub-backup.service -n 100 --no-pager
```

7. 在阿里云盘确认文件存在后，再启用周六18:00定时器。

## 届时需要用户确认

- 用哪个阿里云盘账号完成授权；
- 云端目标目录（默认 `/载衡人力负荷备份`）；
- 云端是否长期保留全部周备份（默认长期保留，VPS仍只保留最近3份）。

授权令牌只保存在VPS的受限配置目录，不写入项目源码或环境变量文件。
